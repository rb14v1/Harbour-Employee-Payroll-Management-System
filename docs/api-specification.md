# API specification

Base path `/api/v1`. Interactive reference at `/api/docs` (OpenAPI 3, generated from `backend/src/openapi.ts`).

## Conventions

- **Auth:** `POST /auth/login` sets an httpOnly `pms_session` cookie (SameSite=Lax, Secure when `COOKIE_SECURE=true`) and returns `csrfToken`. Send it as `X-CSRF-Token` on every non-GET request. `GET /auth/me` returns the token again after a page reload.
- **Success:** `{ "data": ... }`, lists add `"meta": { page, limit, total, totalPages }`.
- **Error:** `{ "error": { "code", "message", "details?", "requestId" } }`.
- **Status codes:** 400 validation, 401 unauthenticated, 403 forbidden or bad CSRF, 404 not found or out of scope, 409 invalid state or conflict, 413 payload too large, 422 business rule failure, 429 rate limited.
- **Money:** integer paise in every request and response (`500000` = INR 5,000.00). CSV imports take rupees with up to two decimals.
- **Pagination:** `page` (default 1) and `limit` (default 20, max 100).
- **Validation:** body, query and path parameters are validated with Zod. Unknown keys are dropped, so client-supplied `organizationId`, `role`, `employeeCode` or status fields are ignored.
- **Rate limits:** 600 requests per minute per IP overall; 20 per 15 minutes on login, forgot-password and reset-password.

## Endpoints

Permission column uses the keys in `shared/permissions.ts`. "scoped" means results are filtered to what the caller may see.

### Auth

| Method and path | Permission | Notes |
|---|---|---|
| POST `/auth/login` | public | Five failures lock the account for 15 minutes |
| POST `/auth/logout` | session | Revokes the server-side session |
| GET `/auth/me` | session | |
| POST `/auth/forgot-password` | public | Same response whether or not the account exists |
| POST `/auth/reset-password` | public | Token is single-use, 30 minute expiry; revokes all sessions |
| GET/POST `/users`, PATCH `/users/:id`, POST `/users/:id/revoke-sessions` | `user:manage` | You cannot deactivate or re-role yourself |

### Employees

| Method and path | Permission | Notes |
|---|---|---|
| GET `/employees` | session, scoped | Query: `q`, `departmentId`, `designationId`, `status`, `sort`, `order`, paging. No bank or PAN fields |
| POST `/employees` | `employee:write` | Code generated by the server |
| GET `/employees/:id` | session, scoped | Bank and PAN masked, only for `employee:sensitive` holders and the employee |
| PATCH `/employees/:id` | `employee:write` | |
| POST `/employees/:id/deactivate` | `employee:write` | Needs `exitDate` and `reason` |
| POST `/employees/import` | `employee:write` | multipart `file` (.csv, 1 MB, 1000 rows). Partial import with `{created, failed, errors[{row,message}]}` |
| GET `/employees/export` | `employee:read` | CSV, audited, no sensitive fields |
| GET `/employees/:id/payroll-history` | `payroll:read` or self | Employees see finalised periods only |
| GET/POST `/employees/:id/salary-revisions` | `salary:read` / `salary:manage` | Append-only; new effective date must be later than the latest |

### Payroll

| Method and path | Permission | Notes |
|---|---|---|
| GET `/payroll/periods` | `payroll:read` | `status` filter |
| POST `/payroll/periods` | `payroll:prepare` | `{year, month, cutoffDate?}`; one per month |
| GET/POST `/payroll/:periodId/inputs` | `input:read` / `input:manage` | Types: unpaid_leave (days), overtime, variable_pay, incentive, deduction, adjustment (paise). New inputs are `pending` |
| POST `/payroll/:periodId/inputs/import` | `input:manage` | CSV `employeeCode,type,value,description`, all-or-nothing |
| POST `/payroll/inputs/:inputId/review` | `input:manage` | `{decision}`; not your own entry |
| POST `/payroll/:periodId/simulate` | `payroll:prepare` | Nothing stored |
| POST `/payroll/:periodId/calculate` | `payroll:prepare` | Rerun needs `reason` |
| GET `/payroll/:periodId/summary` | `payroll:read` | Totals, by department, by deduction, approval history |
| GET `/payroll/:periodId/entries`, `/exceptions` | `payroll:read` | |
| POST `/payroll/:periodId/submit` | `payroll:prepare` | `{comment?, acknowledgeExceptions?}` |
| POST `/payroll/:periodId/approve` | `payroll:approve` | Segregation of duties |
| POST `/payroll/:periodId/reject` | `payroll:approve` | `{comment}` required |
| POST `/payroll/:periodId/finalize` | `payroll:finalize` | Creates payslips |
| POST `/payroll/:periodId/payment-reference` | `payment:record` | `{reference, paymentDate, amount}`; amount must equal batch net |
| POST `/payroll/:periodId/reconcile` | `payment:record` | |
| POST `/payroll/:periodId/cancel` | `payroll:prepare` | Only before approval |
| POST `/payroll/:periodId/adjustments` | `payroll:prepare` | For finalised periods; applied to a later editable period |
| POST `/payroll/adjustments/:id/review` | `payroll:approve` | Not your own request |

Illegal transitions return 409 with `details.status` and `details.allowedFrom`.

### Reports

All require `report:view`. Filters: `fy` (start year of the financial year), `periodId`, `departmentId`, `location`, `format=json|csv|pdf`. Exports are audited. Reports include approved and later batches only.

`GET /reports/payroll-summary`, `/department-costs`, `/deductions`, `/headcount`, `/dashboard`.

### Audit

`GET /audit-logs` (`audit:view`): filters `action` (prefix), `entityType`, `entityId`, `actorId`, `from`, `to`. There are no write endpoints.

### Operations

`GET /health`, `GET /ready` (outside `/api/v1`).
